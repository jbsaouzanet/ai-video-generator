# ai-video-generator

Programmatic explainer videos for **RocketMod Weapon Detect**, built with [Remotion](https://www.remotion.dev/) (React + TypeScript).
One code base renders every cut: the vertical short, the horizontal long-form films, plus animated intro stings and an end card.
Voice-over, music, sound effects and word-synced subtitles are generated by code (local TTS, no samples).

Source of truth for all on-screen copy: <https://rocketmod.org/documentation/weapon-detect/ps5-per-profile>
(what the docs say, and where the video deviates from the brief: [`docs/SOURCE.md`](docs/SOURCE.md)).

## Compositions

| Composition | Format | Length | Category | Render |
|---|---|---|---|---|
| `RocketModWeaponDetectionShort` | 1080x1920 (9:16) | 33.5 s | short | `npm run render:short` |
| `RocketModWeaponDetectionLong` | 1920x1080 | 90 s | long | `npm run render:long` |
| `RocketModPerWeapon` | 1920x1080 | ~117 s | long | `npm run render:perweapon` |
| `RocketModWeaponDetection` | 1920x1080 | 33.5 s | draft | `npm run render:draft` |

`scripts/render.mjs` enforces the deliverable rules before and after each render: **short = vertical 9:16**,
**long = horizontal and at least 70 s**. A render that breaks a rule is moved to `out/rejected/`. Renders never overwrite: each one gets the next free `vN` name.

## Requirements

- Node.js 20+ and npm
- [ffmpeg](https://ffmpeg.org/) / ffprobe on `PATH` (frame extraction, audio mastering, muxing, concat)
- Optional, only to regenerate the voice-over: Python 3.10/3.11 with [Piper](https://github.com/OHF-Voice/piper1-gpl) and/or [Kokoro](https://github.com/hexgrad/kokoro); see [`docs/DEV-NOTES.md`](docs/DEV-NOTES.md)

## Getting started

```bash
npm install
npm run dev          # Remotion Studio
npm run typecheck
```

### Private inputs are not in this repository

Photos, product shots, logos, personal recordings and every generated file are **git-ignored on purpose**:

| Path | What it holds | Status |
|---|---|---|
| `assets/` | source photos, logo artwork, personal portrait / voice recordings | private, not published |
| `public/` | files Remotion serves: derived images, mastered audio, brand SVGs | generated from `assets/`, not published |
| `audio/voiceprints/` | voice-conversion voiceprints (personal timbre) | private, not published |
| `audio/build/`, `out/` | intermediate audio, stems, rendered videos | generated, not published |

To render on a fresh clone you supply your own inputs:

1. `assets/cronus-v2.png`: the device lifestyle photo, then `npm run assets` builds `public/cronus-*.jpg`.
2. `assets/intro-v2.png`: the logo on a pure black background, then `npm run intro:assets` builds `public/intro-logo*.png`.
3. `public/logos/{discord,tiktok,youtube}.svg`: brand icons for the end card.
4. Audio: `npm run audio` (needs the voice tooling) writes `public/audio/*.wav`, or drop your own soundtrack there.

Nothing else is required: all copy, timing and animation live in `src/`.

## Commands

```bash
npm run assets            # build the device photo plates
npm run dev               # Remotion Studio
npm run render:short      # | render:long | render:perweapon | render:draft
npm run preview           # ffmpeg stills at key timestamps -> out/preview/
npm run audio:voice       # local TTS voice-over + word timeline
npm run audio             # music + sfx + voice mix, mastered to -16 LUFS
npm run mux               # put the soundtrack on an already-rendered silent mp4
npm run intro:render      # every intro variant in 16:9 and 9:16
npm run typecheck
```

`DELIVERY_DIR=<path>` sets where finished renders are also copied (default `~/Koofr/RocketAIM`, `DELIVERY_DIR=none` disables the copy).

## Project layout

```
src/
  timeline.ts, tl.tsx, tall.ts    all timing: scenes, camera keyframes, OLED events (per format)
  components/                     Cronus hero, OLED screen, profile cards, docs panel, subtitles...
  scenes/                         one file per scene (wide + tall variants)
  long/, perweapon/               long-form chapter packs and the voice-first per-weapon film
  intro/, outro/, pitch/          sting variants, end card, pitch clips
  subtitles/                      word-synced caption data
audio/                            voice scripts (*.script.json) and .srt captions
scripts/                          render, audio synthesis/mastering, delivery, intro/outro publishing
docs/                             SOURCE.md (copy rules), DEV-NOTES.md (detailed pipeline notes)
```

Design idea: one continuous camera. The device is not part of any scene; it is rendered once at stage level and driven by keyframes,
so scenes only own the graphics around it. The device pixels are never repainted, only masked, lit and overlaid.

More detail (audio pipeline, subtitles sync, intro variants, final assembly, voice engines) is in [`docs/DEV-NOTES.md`](docs/DEV-NOTES.md).
Shipping a new topic (a new platform of an existing mode, or a new mode entirely)? Start from [`docs/NEW-VIDEO-PLAYBOOK.md`](docs/NEW-VIDEO-PLAYBOOK.md).
